# Что нашлось в документации и что из этого включено

Прочёсано 174 страницы официальной документации Claude Code и Agent SDK
(`code.claude.com/docs`), плюс разобран установленный пакет SDK 0.2.156:
его список опций — это то, что можно проверить, а не вспомнить.

Ниже — только то, что относится к твоему серверу: долгая сессия, запущенная
демоном через Agent SDK, разговор голосом, экрана нет.

Английская версия этой страницы ещё не написана.

---

## Что было выключено

### Системный промпт был пустой

SDK, если не сказать иначе, передаёт CLI буквально `--system-prompt ''`.
Проверено на собранной команде. Системный промпт Claude Code — это и есть
то, что учит его планировать, держаться соглашений, проверять сделанное и
доводить работу до конца. Без него инструменты на месте, а работа вялая.
Снаружи выглядит не поломкой, а «модель поглупела».

### Правила жили не там, где надо

Демон приписывает служебные указания **к каждой реплике**. При сжатии
контекста реплики пересказываются и указания из них пропадают. В
документации это сказано прямо: постоянные правила должны лежать в
`CLAUDE.md` или `.claude/rules/`, потому что они подкладываются заново в
**каждый** запрос и сжатие их не трогает.

### Кэш промпта жил пять минут

Человек говорит урывками: сказал, пошёл дальше, через десять минут сказал
ещё. На пятиминутном кэше каждая следующая реплика заново оплачивает весь
разговор и заново его ждёт. Час — это ровно про такой разговор.

### Не было запасной модели

Перегруженная модель — это тишина в ухе. Не сообщение об ошибке, не
«попробуйте позже», а просто ничего. `fallback_model` переключает сессию на
запасную и возвращается к основной на следующем ходу, когда перегрузка
прошла.

### Ultracode не был включён

Отдельный ключ настроек: сессия идёт на `xhigh` усилии, и Claude **сам
планирует воркфлоу** на каждую содержательную задачу, вместо того чтобы
ждать, пока попросят. Это самый большой рычаг из всех найденных, и он
включается одной строкой.

## Что включено сейчас

### В опциях сессии (`daemon/voice_claude/targets.py`)

| Опция                      | Значение                     | Зачем |
| -------------------------- | ---------------------------- | ----- |
| `system_prompt`            | пресет `claude_code` + приписка | настоящий промпт Claude Code плюс рассказ о том, что на этой машине есть |
| `setting_sources`          | `user, project, local`       | всё с диска: CLAUDE.md, правила, навыки, субагенты, настройки |
| `skills`                   | `all`                        | все найденные навыки |
| `fallback_model`           | `sonnet`                     | ответ послабее лучше, чем тишина |
| `max_buffer_size`          | 32 МБ                        | вывод сборки или прогона тестов не обрывает сессию |
| `add_dirs`                 | каталог публикации           | иначе туда нельзя писать |
| `mcp_servers`              | файл, если он есть           | точка расширения без правки кода |
| `model`, `effort`          | из окружения                 | по умолчанию не задаются: см. ниже про ultracode |

### В настройках рабочей папки (`.claude/settings.json`)

| Ключ                         | Значение  | Что даёт |
| ---------------------------- | --------- | -------- |
| `ultracode`                  | `true`    | `xhigh` усилие и самостоятельное планирование воркфлоу |
| `enableWorkflows`            | `true`    | на плане Pro динамические воркфлоу выключены по умолчанию — без этого ultracode остаётся просто высоким усилием |
| `workflowSizeGuideline`      | `medium`  | до десяти агентов на воркфлоу. См. оговорку ниже |
| `promptCacheTtl`             | `1h`      | разговор урывками перестаёт каждый раз пересчитываться |
| `subagentPromptCacheTtl`     | `1h`      | то же для субагентов и фоновых запросов |
| `bashOutputMaxChars`         | 128 000   | длинный лог сборки виден целиком, а не обрезком |
| `taskOutputMaxChars`         | 128 000   | то же для фоновых задач |
| `skillListingBudgetFraction` | `0.03`    | описания навыков не вытесняются из списка |
| `autoMemoryEnabled`          | `true`    | сессия накапливает знание о тебе между разговорами |
| `fileCheckpointingEnabled`   | `true`    | правки файлов можно откатить |
| `env.CLAUDE_CODE_ENABLE_TODO_TOOLS` | `1` | список задач на любой модели: длинная работа перестаёт теряться |
| `env.BASH_DEFAULT_TIMEOUT_MS` | 5 минут  | рендер и сборка не отваливаются по умолчанию |
| `env.BASH_MAX_TIMEOUT_MS`    | 30 минут  | потолок для того, что правда долго |
| `env.MAX_MCP_OUTPUT_TOKENS`  | 50 000    | ответы MCP-серверов не режутся |
| `permissions.deny`           | список    | ключи, токены, `~/.ssh`, `/etc/voice-shell.env` — вне досягаемости |

### На диске в рабочей папке

```
workspace/
├── CLAUDE.md              твой. Кладётся заготовкой один раз и больше
│                          не трогается никогда
└── .claude/
    ├── settings.json      наше, перезаписывается
    ├── rules/             наше: голос, публикация, как работать
    ├── skills/            наше: семь навыков
    └── agents/            наше: четыре субагента
```

**Правила** (`rules/`) — то, что должно действовать всегда: как отвечать в
ухо, куда класть результат, как работать. Лежат отдельно от `CLAUDE.md`
нарочно: `CLAUDE.md` твой и обновление его не трогает, а правила наши и
приезжают с каждым обновлением.

**Субагенты** (`agents/`) — зовутся по имени и работают параллельно:

| Имя          | Модель  | Усилие | Для чего |
| ------------ | ------- | ------ | -------- |
| `scout`      | haiku   | low    | быстро посмотреть, где что лежит. Дёшево, зови пачками |
| `researcher` | по умолч. | high | один узкий вопрос, источники, проверка фактов |
| `critic`     | по умолч. | max  | враждебная перечитка перед «готово» |
| `builder`    | по умолч. | high | вёрстка, сборка, публикация |

## Чего нельзя и что стоит денег

**Ultracode работает не всегда.** Он требует, чтобы у аккаунта были включены
динамические воркфлоу и чтобы модель поддерживала `xhigh`. Первое я закрыл
ключом `enableWorkflows` — на плане Pro они выключены по умолчанию, и без
него ultracode остался бы просто высоким усилием. Второе зависит от того,
какая модель у тебя идёт по умолчанию. Если чего-то не хватает, сессия всё
равно идёт на `xhigh`, но планирования воркфлоу не будет, и узнать об этом
можно только по поведению.

**Воркфлоу в SDK-сессии надо разрешить.** В интерактивном Claude Code
запуск воркфлоу спрашивают у человека; в SDK вопроса нет, и вызов проходит
обычную проверку разрешений. При `PERMISSION_MODE=auto` демон пропускает
его сам. При `guarded` каждый запуск будет спрашивать голосом — это
работает, но надоест.

**Размер воркфлоу я оставил средним — до десяти агентов.** «Большой» — это
до пятидесяти, и на одной голосовой просьбе он способен съесть дневной
лимит подписки, после чего в ухе будет тишина до завтра. Это ровно то, чего
ты просил избежать. Меняется одним словом в `.claude/settings.json`:
`"workflowSizeGuideline": "large"`.

**Явное усилие убивает ultracode.** `CODE_EFFORT` и `CLAUDE_CODE_EFFORT_LEVEL`
идут первыми в порядке разрешения и подменяют собой и `xhigh`, и
оркестровку. Поэтому по умолчанию усилие не задаётся нигде — это проверено
тестом, чтобы не вернулось случайно.

**Часовой кэш дороже пятиминутного** — API берёт за запись в него больше.
Для разговора урывками он всё равно выгоднее, потому что иначе каждая
реплика оплачивает весь разговор заново.

**Коннекторы claude.ai недоступны.** Сервер входит по токену
`claude setup-token`, а такой токен умеет только делать запросы к модели.
MCP-серверы подключаются файлом `/opt/voice-shell/mcp.json` — это
единственный путь. Образец лежит рядом, `mcp.json.example`; ключи в него
вписывать не надо, `${ИМЯ}` подставляется из окружения службы в момент
запуска.

**`bypassPermissions` не работает под root.** CLI его там не принимает, и
это не наша выдумка, а поведение Claude Code. Поэтому демон под root
работает в `acceptEdits` и всё решает своим колбэком.

## Что уже было и работает

Не всё пришлось включать — кое-что уже стояло и просто не было названо.

- **Встроенные навыки Claude Code** доступны и в SDK-сессии: `/code-review`,
  `/verify`, `/run`, `/debug`, `/batch` и остальные. Их не надо ставить, они
  приезжают с CLI.
- **Автопамять** включена по умолчанию: сессия сама откладывает, что узнала
  про тебя и про работу, в `~/.claude/projects/<проект>/memory/`, и читает
  это в начале каждого разговора. Записывает обычными Write и Edit, так что
  работает ровно потому, что файловые инструменты не выключены.
- **Субагенты** были доступны всегда — не было только своих, названных и
  настроенных под задачи.
- **Поиск и чтение страниц** работали с самого начала.

## Что осталось

Найдено, но не включено — каждое со своей причиной.

- **Переключение модели голосом.** SDK умеет `set_model()` и
  `set_permission_mode()` прямо на живой сессии, без потери разговора.
  «Клод, лучшая модель» / «быстро» / «обычно» — это рабочая идея. Не сделал
  сейчас: каждая новая голосовая команда — это четыре языка в словаре,
  разбор фраз на телефоне и новый способ ошибиться, а разбор мы только что
  вычистили. Следующим заходом.
- **Модель по умолчанию.** `CODE_MODEL=best` берёт самую сильную из
  доступных твоему аккаунту. Не ставлю сам: это твои лимиты и твои деньги.
  Ставится одной строкой в `/etc/voice-shell.env`.
- **Песочница** (`sandbox`). Claude Code умеет запускать команды в
  изоляции с белым списком доменов и путей. На сервере, который и так твой
  и больше ничего не делает, это скорее мешает; но если появится чужой код
  — рычаг есть.
- **Хуки.** Двадцать с лишним событий жизненного цикла, вплоть до
  `PreCompact` и `SubagentStop`. Ничего из этого сейчас не нужно; когда
  появится задача вроде «каждый раз после правки прогоняй линтер» — это
  сюда.
- **Glob и Grep** на Linux нарочно выключены: Claude ищет через `find` и
  `grep` в Bash, и это встроенные `bfs` и `ugrep`. Вернуть можно, назвав их
  в `allowed_tools`, но их выключили обдуманно, и я не стал спорить.
