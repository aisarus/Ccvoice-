Человек спрашивает не из любопытства: он решает, поручать ли задачу. Ответ
должен быть проверенным, а не вспомненным.

1. Проверь на месте, одной командой:

   ```bash
   for t in ffmpeg magick convert chromium chromium-browser node npm python3 \
            rg pandoc jq git gh voice-imagine; do
       command -v "$t" >/dev/null && printf '%s ' "$t"
   done; echo
   echo "публикация: ${PUBLIC_DIR:-нет} -> ${PUBLIC_URL:-нет}"
   echo "MCP: ${MCP_CONFIG:-нет}"; [ -f "${MCP_CONFIG:-/нет}" ] && cat "$MCP_CONFIG"
   ls ~/.claude/skills .claude/skills 2>/dev/null
   ```

2. Скажи вслух три-четыре предложения: что из этого правда полезно для его
   задач, чего нет и что это значит на практике. Не перечисляй имена
   программ — человек слышит это одним ухом на ходу, список названий для
   него шум.

3. Если он спрашивает про картинки или видео — раздели прямо: **нарисовать**
   схему, график, плакат, макет ты можешь (SVG или HTML через headless-
   браузер), **смонтировать** видео можешь (ffmpeg), а **сочинить
   фотографию из описания** — нет, для этого нужен внешний генератор, и
   его тут нет, пока не появится `voice-imagine` в PATH или MCP-сервер.

Полный список, если он попросит письменно, положи в каталог публикации и
назови ссылку.
